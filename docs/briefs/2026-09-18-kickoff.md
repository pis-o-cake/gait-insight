# 킥오프 브리프 · 합의된 방향과 협의 안건

2026-09-18 기준으로 사용자와 확인한 프로젝트 방향, 기존 계획서와의 차이, 데이터 후보 검증 상태, 사업비·일정 관련 질문을 정리한 보고다. 이후 결정된 기술 구성은 [현행 아키텍처](../architecture/README.md)와 [설계 제안](../design)에 있고, 범위와 완료 기준은 [루트 README](../../README.md)로 옮겼다.

## 보고 요약

- 공개된 건강한 대조군 보행 데이터(PhysioNet gaitpdb)를 분석·시각화하고 관련 운동정보를 안내하는 웹·모바일 웹 프로토타입으로 방향을 잡았다. 인솔 제작·실시간 센서·질병 분류는 1차 범위에서 뺀다.
- 데이터 형식과 라이선스는 확인했으나 원본 내려받기·대조군 선별·지표 계산은 아직이다.
- 사업비 규모·집행 조건·일정·평가 요구사항은 미확인이며, 상대방에게 확인할 질문 문안을 7절에 준비했다. 실제 메시지는 보내지 않았다.

## 1. 사용자와 확인한 방향

- 프로젝트/레포 이름은 `gait-insight`다. 서비스 표시 이름은 미정이다.
- 노인재활운동과 캡스톤디자인 수준의 프로토타입을 만든다. 상용 제품 완성을 목표로 범위를 확대하지 않는다.
- 1차 단계에서는 직접 인솔을 제작하거나 압력 데이터를 새로 측정하지 않고, 공개된 측정 데이터를 활용한다.
- PhysioNet 데이터 중 건강한 대조군만 추출해서 사용한다. 파킨슨병 환자 데이터와 질병 분류는 현재 목적에 필요하지 않다.
- 데이터를 분석하고 결과를 보여주는 웹·웹앱을 만드는 방향이다.
- 운동 기능은 분석한 보행 특성과 관련된 운동정보를 안내하는 범위로 구체화한다. 데이터–운동 짝짓기 예시를 문서에 제시하고 학과와 연결 기준을 검토한다.
- 기존 HWP 계획서는 확정본이 아니다. 계속 수정할 예정이며, 실현 가능한 방향을 제안해도 된다.
- 사업비 관련 내용을 상대방에게 물어봐야 한다. 금액과 집행 조건은 아직 확인되지 않았다.

## 2. 기존 계획서와 수정 방향

원본 HWP 본문을 읽고 검토했다. 기존 문서는 인솔 제작, 압력·움직임 센서 수집, AI 분석, 맞춤형 운동지도, 지속적인 관리를 포괄한다. 걷기뿐 아니라 러닝·스쿼트·런지도 포함한다.

이를 현재 확정된 요구사항으로 취급하지 않는다. 1차 구현은 공개 보행 데이터 기반 소프트웨어 프로토타입으로 구체화하고, 인솔 제작과 실시간 연동 등은 후속 확장 방향으로 정리하는 것을 제안했다. 원본 HWP는 아직 수정하지 않았다.

계획서 목적 문장 제안:

> 공개된 건강한 대조군의 보행 데이터를 활용하여 좌우 하중 및 보행 특성을 분석하고, 이를 직관적으로 시각화하며 관련 운동정보를 제공하는 웹·모바일 웹 프로토타입을 개발한다.

## 3. 데이터 후보 및 검증 상태

우선 후보는 [PhysioNet — Gait in Parkinson’s Disease v1.0.0](https://www.physionet.org/content/gaitpdb/1.0.0/)다.

공개 보행 및 발바닥 압력·하중 자료를 검색해 PhysioNet과 Zenodo의 후보를 확인했다. PhysioNet 자료는 파킨슨병 연구 목적으로 수집됐지만 건강한 대조군도 함께 측정했고, 센서 위치와 시간별 값의 형식이 공개돼 있어 우선 후보로 제안했다. 환자 데이터를 일반인 데이터로 바꾸는 것이 아니라, 처음부터 함께 들어 있는 건강한 대조군 기록만 선별한다. 기획자용 쉬운 설명과 선별 흐름은 [서비스 검토안 02절](../gait-insight-service-review-v0.5.html#s02)에 정리했다.

공식 설명에서 확인한 사항:

- 전체 데이터는 파킨슨병 환자 93명과 건강한 대조군 73명을 포함한다.
- 건강한 대조군의 평균 연령은 66.3세다.
- 각 발 아래 8개씩, 총 16개 센서의 힘을 기록한다.
- 샘플링 주파수는 100Hz이며, 좌우 각 발 센서 합계도 제공한다.
- 측정값 단위는 힘(N)이다. 압력(kPa 등)으로 그대로 표기하면 안 된다.
- 텍스트 기록, 인구학적 정보와 데이터 형식 설명을 제공한다.
- 공식 페이지에 Open Data Commons Attribution License v1.0이 명시돼 있다. 실제 사용·배포 시 출처 표기와 라이선스 조건을 반영한다.

공개 설명·파일 목록 외에 [데이터 형식 설명](https://physionet.org/files/gaitpdb/1.0.0/format.txt)과 [참가자 정보표](https://physionet.org/files/gaitpdb/1.0.0/demographics.html)를 확인했다. 형식 설명에는 시간·16개 센서값·양발 합계의 19열 구조와 센서 상대 위치가 있다. 참가자 표에는 대조군의 보행 속도와 TUAG 등도 있으며 일부 결측값이 있다. 이 값들을 예측하는 기능은 현재 필수 범위가 아니다. 원시 보행 파일 다운로드·품질 검증·대조군 추출·지표 계산은 아직 하지 않았다.

다음 데이터 작업:

1. 형식 설명과 참가자 메타데이터를 읽고 대조군 선별 기준을 확인한다. 파일명만 보고 임의로 선별하지 않는다.
2. 실험 조건을 확인하고 1차 분석에 사용할 조건을 통일한다. 데이터에는 이중 과제 보행 기록도 일부 포함된다.
3. 참가자 수, 기록 수, 반복 측정의 관계를 확인한다. 73명이라는 설명을 73개 파일로 해석하지 않는다.
4. 대조군 샘플 몇 개에서 시간축, 센서값, 단위, 결측·비정상 구간을 확인한다.
5. 좌우 하중 그래프와 보행 관련 지표를 계산해 보고, 실제로 지원할 기능을 확정한다.

건강한 대조군 기록을 모든 일반인의 정상 기준으로 해석하지 않는다. 이 과제에서는 건강한 대조군의 보행 사례를 분석·시각화하는 데 사용한다.

## 4. 제안된 1차 구현 범위 — 아직 세부 확정 전

사용 흐름:

> 기록 선택 → 저장된 측정 기록 재생 → 보행 지표 및 좌우 비교 → 결과 설명 → 관련 운동정보 확인

| 기능 | 제안 내용 |
| --- | --- |
| 기록 선택 | 대조군의 참가자·측정 기록을 선택 |
| 측정 재생 | 공개 기록을 시간 순서로 재생. 실제 실시간 측정과 구분 |
| 시각화 | 좌우 하중 그래프, 센서 위치별 값, 시간별 변화 |
| 지표 | 좌우 하중 비교, 발 접촉 시간, 보행 주기·변동성 중 검증 가능한 항목 |
| 결과 설명 | 계산된 기록의 특성을 이해하기 쉬운 문장으로 표현 |
| 운동정보 | 분석 특징과 운동 콘텐츠를 짝지어 표시하고 연결 이유 안내 |
| PC·모바일 | 하나의 반응형 웹으로 구성하고 필요하면 PWA 적용 검토 |

지표 계산 구간과 정의는 샘플 확인 후 정한다. 걷는 중 순간적인 좌우 하중 차이를 곧바로 불균형 판정으로 연결하지 않는다. 센서 사이 영역을 보간해 그리는 경우 보간 시각화임을 명시한다.

기술 스택, 화면 수, 로그인, 업로드, 서버 저장, 배포 방식은 아직 정하지 않았다. 우선 저장된 공개 샘플을 선택하는 흐름으로 핵심 기능을 구체화할 수 있다.

### 분석 데이터–관련 운동정보 예시

| 분석 대상 | 연결할 운동정보 후보 |
| --- | --- |
| 여러 걸음의 좌우 누적 하중 차이 | 지지물을 이용한 체중 이동, 옆으로 걷기 |
| 좌우 발 접촉 시간 차이 | 좌우 번갈아 발 내딛기, 보행 연습 |
| 보행 주기의 변동 | 일정한 리듬으로 걷는 연습 |
| 앞뒤 센서군 하중 분포 | 발목 움직임, 지지물을 이용한 뒤꿈치 들기 |

위 짝은 콘텐츠 연결을 논의하기 위한 예시다. 센서값에서 원인 질환이나 근력 저하를 단정하지 않는다. 운동정보 안내는 학과에서 검토한 규칙으로 구현할 수 있으며, 운동 종류가 정답으로 붙은 학습 데이터가 반드시 필요한 것은 아니다. 비교 기준·적용 조건·연결 근거는 별도로 검토한다.

특징별 추천 운동, 추천 이유, 화면 구성과 참고 자료는 [서비스 검토안 07절](../gait-insight-service-review-v0.5.html#s07)을 기준으로 관리한다. 발 부위와 장기 건강의 대응이나 이에 따른 식습관 추천은 포함하지 않는다.

## 5. AI 및 전공 역할에 관한 제안

기획자에게는 **‘숫자는 프로그램이 계산 → 학과가 검토한 기준으로 운동자료 연결 → AI 또는 준비된 문장으로 설명’** 순서로 안내한다. AI가 필요한 부분과 일반 계산으로 가능한 부분을 구분한다. 쉬운 용어 설명은 [서비스 검토안 01절](../gait-insight-service-review-v0.5.html#s01), 원본 계획서 비교표는 [03절](../gait-insight-service-review-v0.5.html#s03)에 있다.

- 하중 비율·접촉 시간·보행 주기 등은 수치 계산으로 처리한다.
- 결과 설명은 문장 템플릿 또는 LLM 활용을 검토할 수 있다. AI 적용은 아직 확정되지 않았다.
- LLM은 글을 이해하고 작성하는 AI다. 원시 센서값 전체 대신 계산 결과·비교 기준·이미 연결된 운동자료를 받아 설명을 작성하도록 제안한다.
- AI 설명을 쓰지 않거나 연결에 실패하면 미리 준비한 문장에 계산 결과를 넣어 보여준다. AI 설명이 숫자를 바꾸거나 검토되지 않은 운동을 추가하지 않는지 확인한다.
- 규칙 기반 계산·콘텐츠 연결을 머신러닝 모델 학습이라고 표현하지 않는다.
- 건강한 대조군만 사용하는 목적에 맞춰, 불필요한 질병 분류 모델을 추가하지 않는다.
- 학과 측은 운동 콘텐츠, 설명 기준, 고령자가 이해하기 쉬운 표현과 화면 구성에 기여할 수 있다.
- 추천 운동을 시연하는 것과 개인별 운동 효과를 입증하는 것은 구분한다.

## 6. 1차 범위에서 제외하거나 후속으로 검토할 사항

현재 사용자 방향상 직접 센서 데이터를 수집하는 작업은 1차 범위에 포함하지 않는다. 다음 항목도 별도 합의 없이 필수 기능으로 추가하지 않는다.

- 인솔 하드웨어 제작·센서 교정·블루투스 실시간 연결
- 러닝·스쿼트·런지까지 분석 대상 확장
- 질병 진단, 낙상 위험도 확정, 교정 효과 검증
- 실제 장기 기록이 없는 상태에서의 운동 전후 개선 분석
- 네이티브 앱 별도 개발 및 상용 서비스 수준의 운영 구성

## 7. 사업비 관련 필수 질문

사업비가 있다는 것, 개발비를 지급할 수 있다는 것, 그 금액이 얼마인지는 각각 확인이 필요하다. 현재 확정된 금액이나 집행 규정은 없다.

상대방에게 확인할 내용:

1. 이번 캡스톤에 배정된 총사업비는 얼마이며, 그중 웹·웹앱 제작에 사용할 수 있는 예산은 얼마인가?
2. 해당 사업비로 외부 개발비·용역비를 지급할 수 있는가? 학교 또는 사업 담당자에게 확인된 내용인가?
3. 지급 대상의 자격이나 계약·견적서·증빙 요건은 무엇인가? 개인에게 지급 가능한가, 사업자 계약이 필요한가?
4. 서버·도메인·AI API 등의 비용을 집행할 수 있는가? 개발비와 운영비를 별도로 잡는가?
5. 예산 집행 기한과 지급 시점은 언제인가? 선금·중도금·완료 후 지급 중 어떤 방식인가?
6. 지급 및 검수에 필요한 결과물은 무엇인가? 시연, 소스코드, 보고서, 배포 URL 등의 요구가 있는가?
7. 과제 종료 후 운영비 부담과 유지보수·수정 범위는 어떻게 정할 것인가?

이 질문은 확인 목록이며, 학교 규정에 대한 판단이나 집행 가능 여부를 확정한 것이 아니다. 사업비 규모·사용 가능 항목·일정·산출물을 확인한 뒤 구현 범위와 견적을 협의한다.

### 먼저 전달할 짧은 질문 문안

> 우선 공개된 건강한 대조군의 보행 데이터를 활용해 분석 결과를 PC와 모바일에서 확인할 수 있는 웹앱 프로토타입으로 방향을 잡으려고 합니다. 제작 범위를 정하려면 이번 캡스톤 총사업비와 그중 웹앱 개발에 사용할 수 있는 예산을 알 수 있을까요? 학교 사업비로 외부 개발비 지급이 가능한지, 필요한 계약·증빙과 지급 일정도 확인 부탁드립니다. 서버나 AI API 비용을 별도로 사용할 수 있는지와 최종 제출·발표 일정도 함께 알려주시면 범위를 구체화하는 데 도움이 됩니다.

위 문안은 전달용 초안이다. 실제 메시지는 보내지 않았다.
