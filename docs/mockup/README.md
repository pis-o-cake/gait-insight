## 데스크톱 목업 · gait-insight-demo.html

**파일은 하나**(`gait-insight-demo.html`). 상단 우측 원형 스와치로 테마(시안)를 바꾸면 색만 바뀌고 화면·상태는 유지된다. 선택은 `localStorage`에 저장된다.

| 시안 | 테마 키 | 이름 | 색 | 히트맵 기본 |
| --- | --- | --- | --- | --- |
| 1 (기본) | v4 | 세이지 | 라이트 그린그레이 · 왼발 딥틸 / 오른발 코럴 | moss |
| 2 | v1 | 샌드스톤 | Oura 웜톤 · 왼발 올리브 / 오른발 브라운 | warm |
| 3 | v2 | 나이트 | 다크 남색 · 왼발 아이스 시안 / 오른발 앰버 | ember |
| 4 | v3 | 코발트 | 라이트 모노톤 · 왼발 잉크 / 오른발 코발트 | plasma |

UX·마크업·JS는 공통(시안 3의 "플레이어" 골격). 테마는 `html[data-theme]`에 걸린 `:root` 토큰 묶음이고, 히트맵 팔레트·캔버스 오버레이 색도 테마별로 스크립트의 `THEMES`에서 갈아 끼운다.

빌드: **HTML(마크업·JS)이 원본**이고 직접 편집한다. `build/build.py`가 `build/base-style.css`(공통 UX 스타일) + `build/skins.py`(테마 토큰)를 조립해 HTML의 `<style>` 블록만 교체한다. 스타일을 고쳤으면 실행:

```bash
python3 docs/mockup/build/build.py
```

테마를 추가·수정하려면 `skins.py`의 `SKINS`(토큰 CSS, 팔레트, 기본 팔레트, 좌우 색)와 `THEME_ORDER`, 그리고 HTML §2의 `THEMES` 객체(팔레트·기본 팔레트)를 함께 고친다. 빌드가 둘의 팔레트 키가 어긋나면 실패한다.

## 모바일 목업 · gait-insight-mobile.html

휴대폰에서 보는 용도로 **셸만 다시 짠 별도 파일**이다. 데이터 생성·지표 계산·히트맵 렌더는
데스크톱 목업과 같은 코드를 그대로 쓰고, 화면 골격과 조작부만 손가락 기준으로 바꿨다.

| 데스크톱 | 모바일 |
| --- | --- |
| 상단 내비의 단계 세그먼트(1 기록 / 2 분석 / 3 추천 운동) | **하단 탭바** 3탭(기록·분석·운동). 기록 선택 전에는 분석·운동 탭이 잠긴다 |
| 스테이지 위 표시 설정 팝오버 | **바텀시트**(딤 + 손잡이, 바깥 탭·Esc로 닫힘). 재생 속도도 여기로 옮겼다 |
| 재생 독 한 줄 `[재생][처음] 시간 ──슬라이더── [배속]` | 탭바 위 **2행 독** — 1행 시크바, 2행 `[재생][처음] 시간` |
| 카드 안에 놓인 히트맵 스테이지 | 화면 좌우 끝까지 **풀블리드**, 좌우 순간값 배지는 독에 가리지 않게 상단으로 |
| 시연용 안내 항상 펼침 | `<details>`로 **접어 둠** — 첫 화면에 기록 카드가 보인다 |

- **터치**: 시크바 손잡이 26px·히트 영역 44px, 탭바·아코디언·주요 버튼 44px 이상. `env(safe-area-inset-*)`로 노치·홈 인디케이터를 피한다.
- **테마·언어**: 데스크톱과 동일하게 테마 4종을 지원하고(`localStorage`), 탭 라벨은 `STR`의 `tab.*`에 있다.
- **빌드**: `build/build.py`는 데스크톱 파일만 조립한다. 모바일 파일은 `<style>` 끝의 `모바일 셸` 블록을 **직접 편집**한다.
- **로직을 고칠 때**: `STR`·`RECORDS`·`analyze()` 같은 공통 부분을 바꾸면 **두 파일 모두** 반영해야 한다.

### 확인한 것 (2026-09-22)

- **가로 스크롤 0**: 320 / 390px 모두 `scrollWidth == innerWidth`. macOS Chrome은 창을 500px 아래로 줄이지 못해 390px iframe 안에서 측정했다.
- **흐름 16항목 통과**: 틀린 비밀번호 거절 → `admin`/`0000` 로그인 → 탭바 잠금 → 기록 선택 → 히트맵 캔버스 렌더 → 시트 열고 바깥 탭으로 닫기 → 탭바로 운동·기록 이동.
- **시트 쌓임 순서**: 시트는 `document.body` 직하로 옮겨 붙인다. 스테이지 안에 두면 스테이지가 만든 쌓임 맥락에 갇혀 재생 독·탭바 아래로 깔린다.
- 남은 확인거리: 실기기(iOS Safari·Android Chrome), 시트 드래그로 닫기, 가로 모드.

## 화면 흐름

`#/login` 로그인 → `#/list` 내 기록 선택 → `#/analysis/<id>` 보행 분석(히트맵·그래프·지표) → `#/exercise/<id>` 관찰된 특징과 추천 운동. 해시로 화면만 전환하며 브라우저 뒤로가기가 동작한다.

- **로그인**: 시연용 고정 계정 `admin` / `0000` (`CFG.demoAuth`). 틀리면 오류 문구 + 흔들림. 인증 상태는 `sessionStorage`(탭 닫으면 해제), 미인증이면 어느 주소로 들어와도 로그인으로 보낸다. 내비 "로그아웃"으로 해제. 실제 제품은 서버 인증으로 대체.
- **내 기록**: "안녕하세요, 이수민님" 인사 + 기록 3개(산책 제목·측정 일시·스파크라인). 예시 기록을 사용자의 실제 기록처럼 보여준다. 상단 **시연용 안내** 박스에 "실측 데이터가 없어 미리 넣어둔 예시를 내 기록처럼 보여주며, 기록 선택 기능은 실제 제품에 없다"는 설명과 각 기록이 맞춘 전문가 자료의 대상자 유형(아침 산책 = 유형 1 / 퇴근길 걷기 = 유형 3 / 공원 한 바퀴 = 유형 2)을 적어 둔다. 유형 문구는 이 안내에만 나오고 카드·분석 화면에는 일시만 표시.

| 화면 | 내용 | 조작 |
| --- | --- | --- |
| 기록 선택 | 예시 기록 3개 (전문가 자료 유형 1·3·2의 가상 사례값), 각 10분 · 100 Hz(앞 20초 정적 측정 + 자유 보행), 6초 스파크라인 | 행 선택 |
| 보행 분석 | 양발 보간 히트맵, 하단 재생 독과 표시 설정 팝오버, 전체 10분 개요 + 현재 시점 ±5초 확대 그래프, 지표 M01~M10(체중 부하·지지 시간·리듬과 압력 이동·보행검사 입력 4묶음) 비교 막대, 대상자 유형 판정 요약 | 재생·일시정지·처음으로, 시간 이동, 속도 0.5~30배, 팔레트, 표시 하한, 윤곽·센서·CoP 오버레이, 기록 바로 전환 |
| 추천 운동 | 판정된 유형 블록: 자료 소개 → 1 판정 근거(수치) → 2 권하는 이유 → 3 운동 프로그램(자료 그림·목적·운동량·방법·주의) → 4 운동 후 재평가 표(이번 측정값 포함). 아래 펼침에 측정 항목·원인/잠재적 문제·진행 과정·전후 비교 예시·최종 평가·과제 적용. 그다음 더 살펴볼 점, 다른 대상자 유형 | 방법·주의사항 펼치기, 자료 항목 펼치기, 분석으로 복귀 |

## 시안 1 (샌드스톤) 스킨 메모 · 공통 사항

`docs/references/design-references.md`의 **6 Oura(스킨)** 참고. 네 테마 모두 플레이어 골격을 공유하며, 여기서는 샌드스톤 테마의 색 선택만 적는다.

- 스킨: 샌드스톤 배경(`#f7f1e8`), 크림 카드(`#fefaef`), 필 버튼, 24px 라운드, 그림자 없음. 히트맵 기본 팔레트도 웜톤.
- 폰트: **Pretendard**. 온라인이면 jsDelivr CSS로 로드, 오프라인이면 로컬 설치본 → 시스템 폰트(Apple SD Gothic Neo / Malgun Gothic) 순으로 자동 대체. 완전 오프라인 배포에 Pretendard를 강제하려면 woff2를 base64로 `@font-face`에 내장한다(약 2 MB 증가).
- 지표: 지표마다 왼발·오른발 **비교 막대 + 상태 칩**과 한 줄 뜻풀이. 기준을 넘은 상태(차이 있음·변동 있음·앞/뒤쪽 치우침)는 **빨강에 가까운 주황 칩**, 괜찮은 상태는 회색/연한 칩. M03·M04는 기준선(변동 기준 / 50%) 표시.
- 특징→운동: 분석 화면은 요약(눈에 띄는 특징 n가지 + 제목)과 버튼까지만. 3번 화면에서 특징마다 쉬운 말 제목 / 수치 근거 / 권유 이유 / 운동 카드를 한 블록으로 보여준다. 권유 문장은 `LINK_RULES[].reason`, 제목·근거 문장은 `STR`의 `ex.M0x.head.*`, `ex.M0x.obs.*`.
- 데이터 크기: 10분 × 100 Hz = 60,000 샘플. 센서값은 평면 `Float32Array`(`left[s*8+k]`), 생성 약 20 ms, 지표 계산 약 5 ms. 개요 그래프는 구간별 최대값으로 다운샘플.

## 나이트(v2) 테마 메모

`docs/references/design-references.md`의 **11~13번** 참고. 헬스·운동 앱 클리셰(그린·크림·둥근 필)를 피하고, 모던 제품 페이지 톤으로 잡았다.

- 배경 `#0b1016` 남색 계열(순검정 아님). 층위는 그림자 대신 **표면 밝기**로: 배경 → 카드 `#121922` → 타일 `#1a2330` → 트랙·칩 `#26313f`. 보더는 흰색 7~14% 헤어라인.
- 아이덴티티 색은 **왼발 시안 `#5fd4ff` · 오른발 앰버 `#ffb54a`** 두 개뿐. 그래프·막대·상태 칩·추천 블록·브랜드 점 2개까지 전부 이 둘로 통일. 별도 포인트 컬러(네온 그린 등) 없음. 기본 버튼은 흰색.
- 내비는 반투명 글래스(`backdrop-filter`), 단계 표시는 세그먼트 필. 히트맵 스테이지는 더 어두운 웰(`#080c11`) 위에 발이 떠 보이도록 은은한 방사형 명암만.
- 대문자 눈썹 라벨·그라데이션 장식·카드 호버 애니메이션은 넣지 않았다(생성형 디자인 티 방지).
- 히트맵 팔레트: `ember`(기본, 어둠→자주→주황→노랑), `ice`, `jet`, `mono`. 팔레트 `[0]`은 하중 없는 발 실루엣 색이라 스테이지보다 한 단계 밝게 둔다.
- 캔버스 오버레이 색(윤곽·센서·CoP)은 `:root`의 `--viz-*` 토큰을 `vizInk()`로 읽는다. 스킨만 바꿀 때 JS 수정 불필요.
- 고령자 가독성 검토가 필요하면 토큰만 라이트 값으로 바꿔 3안을 뽑을 수 있다.

## 공통 UX (플레이어 골격) · 코발트(v3) 테마 메모

`docs/references/design-references.md`의 **14~16번** 참고. 헬스 앱이 아니라 "기록을 재생하는 플레이어" 같은 모던 제품 페이지를 목표로 했다.

- 색: 캔버스 `#f1f2f4`, 카드 흰색, 보더·그림자 없음(톤 차이로만 구분). **왼발 = 잉크, 오른발 = 코발트 `#2f4dff`**. 강조색은 코발트 하나. 히트맵 기본 `plasma`.
- 골격: HUD 사이드 패널을 없애고 **하단 고정 재생 독**(재생/처음으로/시간 이동/배속 세그먼트)으로 옮김. 스테이지는 전체 폭 히어로, 큰 시간 표시와 좌우 순간값 배지. 팔레트·표시 하한·오버레이는 스테이지 우상단 "표시 설정" 팝오버(바깥 클릭·Esc로 닫힘).
- 기록 선택: 카드 3개 대신 **큰 행 + 6초 스파크라인**(왼발 잉크/오른발 코발트) 미리보기. 분석 화면 상단에 기록 A/B/C 세그먼트 탭.
- 지표: 4열 벤토 타일, 큰 숫자 2개(왼/오)와 얇은 비교 막대. 상태 칩(검정 = 차이 있음, 회색 = 차이 작음).
- 모션: 화면 진입 1회 스태거(`--i`), 지표 카운트업, 막대 채움, 독 슬라이드업, 단계 표시 슬라이딩, 운동 카드 `grid-template-rows` 펼침. `prefers-reduced-motion`이면 전부 끔.
- 특징 블록: **세로 스텝 플로우** 1 관찰한 것 → 2 권하는 이유 → 3 추천 운동. 왼쪽 레일에 번호 노드, 뷰포트에 들어오면 노드 점등 → 레일 선 성장 → 카드 등장이 0.45초 간격으로 이어진다(IntersectionObserver, 1회). 좌우 2단(근거 | 운동 카드)은 왼쪽이 비어 보여 폐기.
- 대문자 라벨·그라데이션 장식·화살표 남발은 피했다. 화살표 아이콘은 이동 버튼 2곳에만.

## 세이지(v4) 테마 메모

- 캔버스 `#f2f5f1` 그린그레이, 흰 카드, 보더 없음. 강조 딥틸 `#0f6e63` 하나. **왼발 딥틸 / 오른발 코럴 `#ff6b3d`** — 보색 대비라 그래프·막대 구분이 가장 또렷하다.
- 차이 있음 칩은 코럴, 차이 작음 칩은 틸 연한 톤. 히트맵 기본 `moss`(회녹 → 틸 → 잉크), 대안 `sunset`(살구 → 코럴 → 와인).

## 갈아엎을 때 손대는 곳

파일은 `<style>` 하나 + `<script>` 하나. 스크립트는 번호 섹션으로 나뉜다.

| 바꾸려는 것 | 위치 |
| --- | --- |

## 예시 데이터에 대해

- PhysioNet gaitpdb 형식(시간, 왼발 8, 오른발 8, 합계, 100 Hz)을 흉내 낸 **합성 신호**. 센서 위치는 공식 format.txt의 상대 좌표.
- 정상·질환 같은 이름을 붙이지 않는다. 화면 상단 배너로 시연용임을 항상 표시한다.
- 기록 3개는 `docs/analysis`의 스마트인솔 상세판 3종이 든 가상 사례값에 맞췄다(유형 1: 정적 42:58·입각기 0.56/0.66초·한발 지지 0.32/0.41초, 유형 2: 보장 48/60cm·0.80 m/s, 유형 3: 49:51·분당 110걸음·1.12 m/s). 보장·보행 속도는 인솔로 잴 수 없어 `walkTest`(10m 보행검사 + 영상 분석 값)로 따로 넣는다.
- 측정 항목·원인·운동(목적·방법·운동량·주의)·재평가·진행 과정·비교 예시 문구는 자료 원문 그대로다. 자료에 판정 수치가 없어 `CFG.rules` 임계값만 **학과 확인 전 시연값**이다.

## 전문가 자료 반영 (2026-11-17)

`docs/analysis`의 스마트인솔 상세판 3종(좌우보행불균형·좌우보폭차이·정상보행유지)을 두 목업에 같은 내용으로 반영했다.

- **판정**: 기록마다 유형 1(좌·우 체중 부하 불균형)·유형 2(좌·우 보폭 차이)·유형 3(정상 보행 유지) 중 하나. 유형 1·2의 주 지표가 기준을 넘지 않으면 유형 3이다. 유형 3 자료의 '잠재적 문제'(리듬 불규칙·압력 패턴·속도 저하)는 "더 살펴볼 점"으로 따로 낸다.
- **자료 전수 대조**: 자료의 문단·표 칸을 목업 본문과 기계적으로 대조했다. 화면에 넣은 것은 대상자 설명, 측정 항목, 원인·잠재적 문제와 추가 확인 방법, 운동(목적·방법·운동량·주의 + 자료 그림 22장), 재평가 항목, 측정 진행 과정, 최종 평가다. 개념도 2장(보장·보폭, 압력중심 이동 경로)은 SVG로 다시 그렸다.
- **일부러 뺀 것**: 제품 화면에 둘 이유가 없는 다섯 묶음이다.
  - 자료 작성 경위·문서 간 비교 문장("이번 자료는 …과 연계하여", "기존 첫 번째 유형이 …", "제공된 조사자료의 10가지 운동을 모두 반영하고")
  - 그림이 채팅 사진을 대신한 도식이라는 작성 메모 3건
  - 가상 운동 전·후 비교표 3개. 기록 값과 다른 가짜 수치라 사용자 기록으로 오해할 수 있다. 표의 주의 문장은 각 유형의 재평가 주석으로 옮겼다
  - 캡스톤디자인 과제 적용 및 기대효과, 추가 개발 방향(학생 과제 계획이며 화면 내용이 아니다)
  - 유형 1·2 원인 표의 '이번 측정값' 칸. 원인은 별도 검사로 확인한다고 자료가 밝혀 인솔 값을 원인 옆에 두지 않는다
- **자료보다 엄격하게 맞춘 것**: 유형 2는 자료대로 보장(보행검사)으로만 판정하고, 자료에 없는 인솔 대리 지표인 걸음 시간(M05)은 보조 근거로만 보인다. "더 살펴볼 점" 이름은 유형 3 자료의 잠재적 문제 이름(압력 이동 패턴 변화·리듬 불규칙성·보장 및 보행 속도 변화)을 쓴다. 추가 개발 방향의 세부 유형 이름은 자료가 검증 전이라고 밝혀 쓰지 않는다.
- **확인**: headless Chrome으로 모바일 320·390px, 데스크톱 768·1280px에서 가로 스크롤 0, 콘솔 오류 0. 세 기록이 각각 유형 1·3·2로 판정되고 지표 값이 백엔드 `metrics.py`와 같다.
- **UI 정리**: 운동 카드는 방법·주의사항을 접지 않고 모두 보여 주며 같은 줄 카드 높이를 맞췄다. 모바일(480px 이하)의 단계 흐름은 왼쪽 레일을 없애고 카드를 전체 폭으로 편다. 목록 미리보기는 정적 구간이 아니라 보행 시작 뒤 6초를 그리고, 하중 그래프에 정적 측정 구간을 음영으로 표시한다. 한글은 `word-break:keep-all`로 단어 단위로 줄을 바꾸고, '좌·우'·'전·후'는 가운뎃점에서 끊기지 않게 붙였다.
- 남은 확인거리: 오프라인 재확인, 실기기, 내장 그림 때문에 커진 파일 크기(약 1.4 MB)로 메신저 전달이 되는지.

## 전달 방법

**`gait-insight-demo.html` 파일 하나만 보내면 된다** (약 1.4 MB · 운동 그림 22장 내장). 받은 사람이 더블클릭하면 브라우저에서 바로 열린다. 설치·서버·인터넷 불필요.

- **폰트 설치 불필요.** 인터넷이 되면 jsDelivr CDN에서 Pretendard 웹폰트를 내려받아 그대로 적용된다(CSS 1건 + 사용 글자에 해당하는 woff2 서브셋 몇 건). 받는 사람이 아무것도 설치할 필요 없다.
- 인터넷이 없거나 CDN이 막힌 망이면 시스템 한글 폰트(Apple SD Gothic Neo / 맑은 고딕)로 자동 대체된다. 레이아웃·기능은 동일하고 글자 모양만 달라진다. 폰트까지 보장해야 하면 woff2를 base64로 `@font-face`에 내장하면 되지만 파일이 약 2 MB 커진다.
- 전달 시 같이 알려줄 것: **로그인 `admin` / `0000`** (화면 안에도 안내가 있다).
- 테마 선택은 `localStorage`, 로그인 상태는 `sessionStorage`에 저장한다. 브라우저가 `file://`에서 스토리지를 막아도(일부 Safari 설정) try/catch로 넘어가며, 로그인은 메모리 상태로 동작하고 테마는 기본값(세이지)으로 뜬다.
- 카카오톡·메일로 보낼 때 확장자가 바뀌지 않게 zip으로 묶는 편이 안전하다.
